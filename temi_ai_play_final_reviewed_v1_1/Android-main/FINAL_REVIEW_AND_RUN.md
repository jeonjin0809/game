# 최종 코드 검토·실기기 시험 안내

**대상:** 4~7세 아동, 교사 감독 아래 대학교 강의실 시연

## 구현 내역 및 변경 근거

| 항목 | 조치 | 확인 범위 |
|---|---|---|
| Android/Gradle | 버전 조합 AGP 9.4.x + Gradle 9.6.0 유지. 별도 JDK 25 다운로드 강제를 제거해 Android Studio 내 Gradle JDK 17+ 사용 | 공식 버전 호환표 대조, 전체 빌드는 미실시 |
| 불필요한 의존성 | 현재 게임에서 사용하지 않는 MediaPipe, CameraX, OkHttp, CAMERA 권한 제외. 레거시 Android 6에서의 충돌 가능성·다운로드량 축소 | 소스/Manifest 확인, APK 빌드는 미실시 |
| 그림 표시 | 안드로이드 이모지 글꼴 대신 17개 로컬 그림을 사용하고 아래에 텍스트를 남김 | 이미지 육안 확인, 로봇 화면 확인 필요 |
| 음성 타이밍 | 설명 완료 후 그림 보기 시작, 질문 완료 후 30초 대기 안내 시작, 피드백 완료 후 다음 버튼 활성화 | 콜백 기반 로직 검토, 실제 TTS 이벤트 확인 필요 |
| TTS/AI 오류 | SDK TTS 콜백 누락 시 시간제한 후 진행. AI 서버 응답 6초 초과 시 오프라인 규칙 사용. 콜백 중복/기한 초과 응답 무시 | 소스 검사, 실기기 네트워크 시험 필요 |
| 교사 기록 | 최근 10회 중 기록 선택 → 세부 표시. 실제 실행된 각 미션과 결정 출처/근거 보존 | 로직 검사, 단말 저장 확인 필요 |
| 저장 안정성 | 완료된 세션과 AI 보고서 변경을 확정 저장(`commit`)하여 저장 실패를 반환 | 소스 검사 |
| 숨바꼭질 사전점검 | 사람 감지 이벤트 1회 이상 실제 수신한 후에만 시작. 로봇 저장 위치 2~3곳, 정지 후 탐색 | Java 시뮬레이션 테스트 통과, 사람 실기기 시험 필요 |

## 교사 시연 순서 (권장)

### 1) Android Studio에서 먼저 확인

- `C:\TemiProjects\Android-main`처럼 **한글 없는 경로**에서 시작
- **File → Settings → Build, Execution, Deployment → Build Tools → Gradle**에서 Gradle JDK 17 이상 선택
- Gradle Sync → `emulatorDebug`로 **Build → Make Project**
- 에뮬레이터 앱 실행 → 기억·이야기 5문제 진행
- 완료 → 교사용 기록 1개 선택 → 오답·힌트 사용 내용과 결정 출처 확인 → 다음 놀이 계획 승인 → 첫/마지막 문제의 미션 재사용 확인

### 2) 노트북 AI 서버 연결 확인

- Windows에서 Python 설치 후 `start_agent_demo.bat` 실행
- 서버 `/health`에 브라우저로 접근: `http://127.0.0.1:8765/health`
- 앱에서 서버 IP 입력(PC 에뮬레이터 `10.0.2.2` 또는 로봇과 같은 Wi-Fi의 실제 IP)
- `MODE=demo`는 **AI 모델이 아닌 규칙 실험**. 실제 모델을 위해서는 노트북 환경변수 `OPENAI_API_KEY` 필요
- 모델 호출이 되었다면 기록의 결정 출처가 실제 AI로 표시되는지 확인. 실패 시 오프라인 표시 확인

### 3) 실제 temi에 설치한 다음 (강의실 빈 공간)

- `temiDebug`로 빌드하고 실제 로봇 연결 후 설치
- 앱에서 TTS 말하기가 한국어로 완성되는지 확인. 가끔 중간에 끊긴다면 보고서/게임 품질보다 이 문제를 먼저 해결
- **기억·이야기 게임은 로봇이 움직이지 않음**. 밝은 화면, 이미지 표시, 누르는 영역, TTS 순서, 무선 연결을 확인
- 숨바꼭질: 빈 강의실에서 지도 작성 → 평평한 장소 2~3곳 저장 → 감지 권한 설정 → 진행자가 전방에 서서 감지 테스트 → 참가자 없이 순찰 경로 및 긴급 정지 테스트
- 계단식 강의실의 단차 근처, 아동이 뛰어드는 복도, 충전 위치를 게임 경로로 사용하지 말 것
- 감지 중복 방지에는 얼굴 인식이 없으므로 발견된 사람은 별도 대기구역으로 이동해야 함

## 실기기 합격 기준

- [ ] `temiDebug` 설치·시작 성공
- [ ] **그림/글자**가 다 표시되고 다섯 미션을 끝까지 진행
- [ ] 음성 설명이 끝나고 그림 보기 시간이 시작됨 (실기기에서 직접 확인)
- [ ] 힌트·예시 버튼 터치 시 중복 응답/크래시 없음
- [ ] AI 서버가 꺼져도 다음 문제와 기록 저장 성공
- [ ] 교사 승인 후 첫 번째와 마지막 미션이 승인한 유형으로 진행
- [ ] 사람 감지 사전 테스트를 통과해야 숨바꼭질 시작 가능
- [ ] 모든 이동 목표·경로가 안전하고 교사가 긴급 중단 가능
- [ ] 5분·10분 안내가 게임 시작 시각 기준으로 작동
- [ ] 종료/화면 이탈 뒤 TTS·이동·타이머가 불필요하게 지속되지 않음

## 알려진 제한

1. **Android SDK 전체 빌드 및 temi 하드웨어 시험을 이 환경에서 실행할 수 없었습니다.** Gradle wrapper가 배포본 다운로드 시 `UnknownHostException: services.gradle.org`로 실패합니다. Android Studio Build Output 확인을 통해 실기기 호환성을 최종 검증해야 합니다.
2. `TemiRobotController`는 기존 0.10.80 SDK 호출 코드를 바탕으로 했습니다. 특히 Kiosk/SETTINGS/Detection Mode는 실제 로봇의 런처 버전과 설정에 영향을 받습니다. 
3. Android가 앱을 강제 종료하거나 게임 화면을 벗어나면 **완료 전 세션은 저장하지 않고 초기화**합니다. 교사에게 잘못된 중간 결과를 보고하지 않기 위한 선택입니다.
4. AI 서버 HTTP는 로그인/암호화가 없는 **신뢰할 수 있는 LAN 시연용**입니다. 공용 Wi-Fi·인터넷 공개·실제 아동 개인 정보 입력에는 사용하지 마세요.
5. 현재 기록은 익명 1인 1세션이며 **같은 아동의 장기 비교나 발달 진단을 지원하지 않습니다.** 정답·힌트·선택에 기반한 짧은 후속 놀이 제안만 제공합니다.
6. 숨바꼭질은 신원 인식이 아니라 **사람 감지 횟수**를 세는 게임입니다. 로봇 이동 중 센서 인식은 보장되지 않으므로 방문 장소에서 멈춰 탐색하는 구조입니다.
7. 사진·영상 카메라 인식은 현재 포함하지 않습니다. 향후 팀의 별도 카메라 모듈과 통합 시 MediaPipe/CameraX 등을 재추가해야 합니다.
